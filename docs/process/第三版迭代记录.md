# 第三版迭代记录（契约 v0.3，2026-11-09）

## 1. 本版依据

以 2026-11-09 的《共同字段与接口约定》v0.3 为准（已替换 `docs/共同字段与接口约定.md`）。相对 v0.2，v0.3 的接口/权限变化：

| 编号 | 契约变化 | 影响方 | A 是否受影响 |
|---|---|---|---|
| C-01 | 发布权限按类型拆分：`lost` 登录即可发布；`found` 需校园身份，未绑定 403 `IDENTITY_REQUIRED` | B（发布接口） | 仅确认 A 的认证状态可供 B 校验 |
| C-02 | 认领可针对 `lost` 或 `found`；`lost` 也可进入交接中；两条路径共用同一认领状态机 | C（认领流程） | 否（A 仍提供登录身份和认证状态） |
| C-03 | “我的发布”页面与列表改由 **A 直接查询 B 的 Post 表**（`publisher_id` 过滤），B 不再提供 `/users/me/posts` | A、B | **是（本版新增）** |
| C-04 | 图片新增 `alt_text`（5～100 字），上传接口改为登录即可 | B（图片） | 否 |
| C-05 | `resolve` 增加 `resolve_note`（5～200 字）；新增 `reopen`；发布支持可选 `request_id` 幂等 | B（信息状态） | 否 |
| C-06 | 内部接口：`require_user` 返回含 `campus_verified`；`get_user_summaries` 含 `campus_verified`；新增 `has_completed_claim`；`require_campus_verified` 仅 B 调用 | A/B/C | 需团队确认字段命名（见 §5） |
| C-07 | 校外人员发布的 `lost`，C 在认领中提示去失物招领处交接 | C | 否（A 只提供认证状态） |

> 契约文件中的【B 注记】属于 B 的实现提醒，A 不实现 B/C 的功能；B、C 的变更由对应负责人按新契约排期。

## 4. 契约一致性说明

- A 的 7 个原有接口（注册/登录/登出/本人资料/绑定）语义未变，v0.3 未修改其字段和错误码。
- 新增 `GET /users/me/posts` 完全按契约 5.1 的查询参数与 `PostSummary` 返回结构实现，默认包含本人全部状态。
- 发布权限拆分、`lost` 认领、图片 `alt_text`、`resolve/reopen` 等属于 B/C 的实现范围，A 只在身份状态上提供支持（`is_campus_verified`）。

## 5. 待团队确认 / 后续

1. 契约 7.3 把公开摘要字段写成 `campus_verified`，而 3.2 的 `UserSummary` 仍是 `is_campus_verified`；A 当前保持 `is_campus_verified`，避免破坏 C 的既有实现。建议团队统一为一个字段名后再改内部函数。
2. B 接入正式发布/图片接口后，`/me/posts` 页面可增加“查看详情/编辑”链接；当前 B 页面未实现，故只提供“查看匹配线索”。
3. C 实现 `lost` 认领后，A 的“我的发布”页面可能需要展示交接中/已完成的 `lost` 状态；当前已支持这些状态筛选。
