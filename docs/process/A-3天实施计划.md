## 8. 手动演示流程（D2-09 / D3 用）

1. 双击「启动失物招领系统.bat」，等浏览器打开 <http://127.0.0.1:5173>；

## 9. 常见坑（踩过就少花 2 小时）

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 密码被 `trim_whitespace` 裁掉空格 | 密码字段一律 `trim_whitespace=False`（已给），登录按原值校验 |
| 2 | 登录失败提示“账号不存在” | 账号不存在/密码错/停用统一 401 同一文案，避免账号枚举 |
| 3 | 绑定码明文入库 | 只存 `sha256` 摘要；比较用 `hmac.compare_digest` |
| 4 | 绑定判定顺序错，导致错误码不对 | 严格按：限流 → 字段 → 本人已绑定(409) → 校区(400) → 锁身份 → 码(400) → 占用(409) → 写入 |
| 5 | 事务没包住，绑定一半留下脏数据 | `bind_campus` 用 `transaction.atomic()`；CampusBinding、DemoIdentity.used_by、User 标记一起成功/失败 |
| 6 | 以为 SQLite 有行锁 | SQLite 无真正行锁；靠 `settings` 里的 `IMMEDIATE` 事务串行化写，`select_for_update()` 只是语义占位 |
| 7 | 出参把 `password`/哈希返回 | 手写 `user_self` 时逐字段列，`assertNotIn("password", ...)` 应始终成立 |
| 8 | 客户端提交 `is_campus_verified` 被接受 | `StrictSerializer` 会拦未知/只读字段 → 400，不要为了让前端“方便”而放宽 |
| 9 | 限流没用原子操作，并发漏计 | `cache.add` + `cache.incr`，不要 `get` 再 `set` |
| 10 | 刷新页面要重新登录被当成 bug | 第一版令牌只存内存（契约 2.2），这是设计，别改成 localStorage |
| 11 | 公开接口带无效令牌返回 200 | 认证先于权限执行，带无效 Bearer 一律 401（C 已有回归用例） |
| 12 | 改了 `posts/`、`claims/`、`common/` 造成别人的用例红 | 自己模块外只做必要的小改动，先跟 B/C 说；`common/` 能不动就不动 |
| 13 | 忘了 `/meta/campuses` 是 B 的 | 拿不到就降级文本输入（页面已写），不要自己造第二套校区 ID |
| 14 | `npm` 在 PowerShell 里报脚本禁止运行 | 用 `npm.cmd test` |
| 15 | 测试里复用同一客户端凭据导致越权假象 | 换用户/换令牌时 `self.client.credentials()` 显式设置或清空 |
